[assistant] Gin stores each route's middleware + final handler as a flat `HandlersChain` ([]HandlerFunc). Flow:

1. **`ServeHTTP`** grabs a pooled `Context` and calls **`handleHTTPRequest`** (gin.go:690).
2. It matches method+path in the radix tree (`getValue`), then sets `c.handlers = value.handlers` — the precomputed slice of global/group middleware followed by the route handler.
3. **`c.Next()`** (context.go:188) drives the chain: increments `c.index` and loops calling `c.handlers[c.index]` in order.

Key mechanic: each middleware calls `c.Next()` itself, so everything before that call runs pre-handler and everything after runs post-handler (unwinding as the recursion returns) — that's how gin gets wrap-around behavior. Middleware that doesn't call `Next()` still lets the outer loop advance to the next handler.

**Abort:** `c.Abort()` (context.go:207) sets `c.index = abortIndex` (`MaxInt8>>1`), so the `Next()` loop condition fails and no later handlers run — hence the ~63 handler cap per chain. After the chain, `handleHTTPRequest` calls `WriteHeaderNow()`. No route match → `c.handlers` is set to `allNoRoute`/`allNoMethod` and run the same way.
